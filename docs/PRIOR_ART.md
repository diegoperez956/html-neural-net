## 2. Logic gates, adders, calculators in HTML/CSS

### 2.1 Silon — SLaks (Schabse Laks), 2015-04 — `silon.slaks.net`, github.com/SLaks/Silon (342★)
- **What it computes**: AND/OR/XOR gates; half adder; full adder; chained 4-bit adder
  (two 4-bit inputs 0–15 → 5-bit sum); a decimal adder ("sum of the two numbers … computed
  – in pure CSS – and displayed in decimal form").
- **JS presence/necessity**: none at runtime ("the site has no Javascript anywhere except
  the Gulpfile to compile my LESS source, and except for Google Analytics").
- **Arithmetic mechanism**: NOT `calc()`. A LESS DSL (`.op(a, and|or|xor, b, result)`)
  expands boolean expressions into truth tables encoded as CSS selectors: sibling `~` = AND,
  comma = OR, `:not(:checked)` = NOT. Runtime is pure selector matching.
- **Inference reality**: none — combinational logic only; truth-table selectors; every
  output is a direct function of checkbox state.
- **Relation to our contribution**: the closest precedent for our **gate-derived netlist**
  idea — build-time generation (LESS) → pure-selector runtime, gates → adders → decimal
  output. Stops at addition; no multiplication, no dot product, no neuron. Secondary:
  css-tricks.com/adders-and-logic-gates-in-pure-css/ (Chris Coyier, 2015-06-08).

### 2.2 Clement Cherlin's full adder (2022-10) — inside the Turing-complete repo above
- **What it computes**: full adder, hard-coded inputs (1+1+1=3 (11b)); input bits are set
  in the HTML, not user-toggleable.
- **JS**: none.
- **Arithmetic mechanism**: `:has()` selectors + animation-timed bit transitions (bits
  flip via non-repeating animations; `animation:none` to force 0→1; half-width "blocker"
  elements synchronize tape motion). Timing-based, not statically-combinational.
- **Relation**: demonstrates an adder in CSS, but animation/timing-driven and
  non-interactive — our checkbox-driven, statically-combinational adders are a different
  mechanism, closer to Silon/Amit.

### 2.3 Amit Sheen, "Building a Computer with CSS" — CSS Day 2025 (pens published 2025-06-03)
- **What it computes**: the seven logic gates (NOT/AND/OR/NAND/NOR/XOR/XNOR); half adder;
  full adder; **5-digit binary adder/subtractor**; binary→decimal converter
  (`counter-increment: total calc(pow(2, var(--i)))`). Talk billed as "building a CPU";
  the demonstrated artifact is a calculator, not an executing CPU.
- **JS presence/necessity**: none — talk states "No JavaScript, no magic"; rendered pen
  pages show empty JS tabs (could not execute to fully verify; see caveats).
- **Arithmetic mechanism**: checkboxes (`data-digit` inputs) → `:has()` selectors set
  intermediate custom properties (`--and1`, `--xor2`, …) → `calc()` does the math:
  `--on: calc(mod(var(--and1,0) + var(--xor2,0), 2))` for sum;
  `--and3: calc(var(--and1,0) * var(--xor2))` and `max()` for carry. Output rendered via
  `counter-reset: content var(--on)` + `::after { content: counter(content) }`.
  So: gates are emulated by `:has()` + custom properties, arithmetic by direct `calc()`
  (including `mod()`, `*`, `max()`).
- **Inference reality**: none — combinational binary arithmetic, interactive checkboxes.
- **Relation to our contribution**: **the strongest overlap for our gates→adders→calculator
  chain.** Same input model (checkbox state), same carrier (custom properties), same
  output model (counter-rendered values), same target size class (multi-bit). Differences:
  he mixes gate-emulation with direct `calc()` arithmetic rather than a pure gate-derived
  netlist; he does not attempt multiplication, dot products, or neurons; he uses `:has()` +
  `calc` (Chromium-friendly) where our brief also contemplates older/`file://`-friendly
  selector-only paths. Pens: codepen.io/amit_sheen/pen/PwqzjVr, emNzEjj, QwbEMRa, yyNJoWE,
  bGJvopM (revision URLs, see notes; bare URLs 404). Slides/links page archived 2025-07-11.

### 2.4 Jane Ori, CSS "Space Toggle" state machine (2020-04; propjockey.github.io/bcd7sdd)
- **What it computes**: BCD→7-segment display decoder driven by real binary logic (space
  toggles = boolean values in custom properties); checkbox inputs. Also the space-toggle
  mechanism itself (boolean logic in custom properties; previously found by Ana Tudor ~2017).
- **JS**: none.
- **Arithmetic mechanism**: custom-property "space toggles" (a token that is either the
  empty string or " " — truthy/falsy in `var()` fallback chains) combined with selectors.
- **Relation**: an alternative boolean-in-CSS encoding to ours; useful prior art for
  "computed styles as data," but not arithmetic.

## 3. CSS neural networks / inference demos

### 3.1 GrahamTheDev, "Pure CSS Neural Network" — dev.to, 2023-10-30 (pen JjwqNJV)
This is the **only genuine CSS-inference demo found**, and it is the critical one.
- **What it computes**: a pre-trained network. Inputs: two coordinates (x,y ∈ [-1,1],
  radio-button grid). Outputs: 4 neurons classifying which quadrant (sign of x, sign of y).
  Weights/biases baked into `:root` custom properties (values like
  `--weights1-1: -0.9807…`).
- **JS presence/necessity**: author states the demo "was actually harder to write than the
  Neural network (as I wanted the demo interface to be pure CSS / HTML too!)"; rendered pen
  page shows empty JS tab (not executed — caveat). No JS is required by the mechanism.
- **Arithmetic mechanism**: forward pass entirely in `calc()` on custom properties:
  dot products (`--output1a: calc(var(--weights1-1)*var(--inputX) + var(--weights2-1)*var(--inputY))`),
  **ReLU** via `max(0, out) + bias`, then **argmax/one-hot** via
  `max(out1..out4)` + squared-difference×1e9 rounding trick (`max(1 - (out - maxOut)²·1e9, 0)`).
  Outputs displayed with CSS counters (`counter-reset: x calc(var(--y) * 100000)` — integer
  hack). Note: no `exp()`, so no sigmoid ("CSS exp() is only supported on Firefox and Safari").
- **Inference reality**: **real inference** — a trained network's forward pass computed by
  the CSS engine. But: single layer (2→4), no hidden layer, linear decision boundaries
  (quadrant classification), pre-trained weights only, **no training** ("training that
  neural network is next to impossible (with CSS) due to limitations on how many calc()
  statements you can have that rely on previous ones").
- **Relation to our contribution**: **the strongest overlap for our neuron/dot-product
  stages.** Our "dot product" and "signed threshold neuron" are, mechanistically, rediscoveries
  of his calc-chain arithmetic (multiply + add + max threshold). Our distinguishing elements:
  (a) **multi-layer** network — a 2-2-1 MLP solving XOR with a hidden layer; Graham explicitly
  stopped at a single layer and no found prior art runs a hidden-layer (non-linear
  decision-boundary) inference in CSS; (b) **binary/threshold** neurons and integer arithmetic
  on gate-derived netlists rather than floating-point calc; (c) full pipeline from checked
  form state through gates/multiply to the MLP in one offline file.
- Follow-up: Graham promised an OCR-in-CSS article; **no such article found** (searched
  his dev.to; **unverified/absent**).

## 6. Strongest originality attack

*The most damaging honest reading of the record, for planning purposes:*

> **"Your gates→adders→calculator pipeline is Amit Sheen (June 2025) with the labels
> changed, and your dot product + threshold neuron is GrahamTheDev (October 2023) with
> integers instead of floats."**
>
> Amit already built, in pure CSS with checkbox state → custom properties → `:has()` →
> `calc(mod/*/max)` → counter-rendered output: all seven gates, half/full adders, a 5-digit
> binary adder/subtractor, and binary→decimal — i.e., your entire bit→gate→adder→calculator
> chain, one year ago, with zero JS. Graham already ran *real inference* in pure CSS:
> pre-trained weights in `:root` custom properties, dot-product forward pass in `calc()`,
> ReLU via `max()`, argmax via a rounding trick, and CSS-only input/output UI. Your dot
> product and neuron stages are the same arithmetic. Cherlin (2022) proved CSS Turing
> complete and even shipped an adder; Jane Ori (2023) and Lyra Rebane (2026) proved CSS can
> tick, store, and execute — so "it's possible" is not a contribution. What remains of your
> plan is: (1) a *gate-only* netlist (no direct `calc` arithmetic) for multiplication and
> dot products — Amit mixes both and Silon stopped at addition; (2) a *hidden-layer* MLP
> (2-2-1 XOR) with binary threshold neurons — Graham explicitly stopped at a single layer
> and no indexed prior art runs a multi-layer inference; (3) one self-contained offline
> file from checked form state to network output. These are real gaps in the found record,
> but they are *increments of composition*, not new computational capability, and the
> burden of proof for claiming them as firsts sits with us, on a stronger search than one
> agent session."

**What actually survives the attack (per the found record, stated as absence-of-evidence):**
no found project combines a gate-derived netlist with multiplication and dot products, and
none executes a multi-layer (hidden-layer) network inference in CSS. Those are the only
defensible distinctives; everything else in the brief's hierarchy has a close, dated,
verifiable predecessor.
